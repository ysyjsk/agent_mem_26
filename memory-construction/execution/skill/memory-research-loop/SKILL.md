## 自主诊断
看到错误、异常分数或成本，先查实际请求、源数据/生成记忆和 usage，区分四类：
- 配置偏离：恢复已冻结配置；先用最小真实配对核对实际发送内容，再补受影响查询，不重构建。
- 统计/检查器错误：离线重聚合、重评，按修改/未修改事实及旧值误用区分，不能靠放松检查宣称通过。
- 维护实现错误：定位源修订→依赖→发布/重载→查询的具体断点，在开发回归中修复并补受影响后缀；记录版本和数据暴露。
- 合规运行的真实负结果：保留方法限制并完成剩余固定实验；不无限调参，也不把负结果当成省略交付的理由。

根据一个有证据的原因，最小修复→必要回归→配对运行→保存数字→继续下一项。修复常规错误和补已授权实验无需逐项请示；仍有可执行工作就继续，不仅报告问题。无法自主解决的外部资源障碍才说明需要什么输入，并先完成独立工作。

## 执行不变量
科学范围看 GOAL/EXPERIMENT_PROTOCOL；参数看 experiment_contract；状态只看 queue。实际请求与产物优先于注释、目录名称和旧 complete 标记。文件存在/退出 0/核验工具通过均不等于研究完成。
运行 execution/verify_evidence.py 做必要结构核验；needs_attention 是修复线索，不是研究终止。缺旧配置记录先核对已有日志，不为补元数据重跑全部实验。
成本必须包括更新、查询 controller、Reader；unknown 不填零。完整 Small 按官方 ID 集合及实际加载快照核对，历史库规模不冒充独立修订样本数。固定公开维护对照不能擅自 deferred 或用冷构建参考替代。

## 复用、资源与收敛
