# 从执行偏差恢复，并自主完成研究
修订 execution-recovery-20261016；不改变 v13 方法或固定实验范围。

## 这次为什么出错
正式 Reader 另写入口绕过开发入口初始化，冻结参数只存在于文字/Manifest；开发数据被重新命名为完整 Small；必做公开维护方法被降为参考；成本汇总与事实检查未经独立证据核对；队列把命令/文件完成当成研究完成。允许负结论被误读成允许缩减交付。
问题不靠更长 Prompt 解决：实际配置共用、必要不变量自动核验、状态单一来源，剩余判断交给执行 Agent。

## 先自行分类，再采取最小动作
| 观察 | 查证 | 自主动作 |
|---|---|---|
| 请求带图/参数与清单不符 | prompt_rows.jsonl 的 messages 是实际发送内容；per_question 的 prompt_messages 可能只是 image_path 版本 | 恢复冻结配置，验证真实请求；只补受影响检索/Reader，保留更新快照 |
| 成本/评分/布尔检查异常 | 原始请求账本、usage、源状态、生成 Event 和最终上下文 | 离线重聚合/重评；检查器按事实角色修正，不先调用模型 |
| 实际发布状态违背源修订或失效合同 | 新旧源、依赖、保存重载、实际检索路径 | 在开发回归中修最小实现错误，新版本补受影响链路；不为绿测试弱化条件 |
| 正确配置下 Ours 仍较差 | 配对样本、完整回答/截断、证据召回和源状态一致性 | 如实记录方法限制，继续已定正式实验；不借 bug 名义无限调参 |
| 网络/资源失败 | 实际错误、进程与服务归属 | 可恢复错误修复续跑；保存成功单元并做其他可执行任务，只有需要外部输入时精准说明 |

每次只选一个有证据的原因，定位到具体入口/请求/指标，最小修复后验证，立即继续下一缺失单元。不要把发现问题当成工作终点，也不要先重审全部历史。缺记录不等于零成本或质量失败；合法旧阶段按依赖复用。

## 已完成的结构修复与下一动作
- execution/experiment_contract.json 是当前期望值；tools/focused_runtime.py 统一应用 flags 和 Reader 参数。正式 Reader 已改为先配置再导入 harness；每个新 run 写 effective_runtime.json。期望值不是运行证明。
- execution/verify_evidence.py --current 离线核对登记的旧正式结果，预期报告 needs_attention。退出 1 指向需要修复的证据，不终止研究；不要让 shell 的 set -e 把整个后续计划一起停止。
- 新运行可显式检查：python3 execution/verify_evidence.py --reader-dir <run>。全库再加 --manifest <new-manifest>；主表再加 --main-table <new-table> --check-queue。--report <new-file> 可保存带原始哈希的报告，拒绝覆盖。
- 首先复用两域 B3/Ours 现有快照，用原四个诊断题得到 8 个修正配置回答。检查实际 requests 无图、Reader 参数及生效 flags 一致，再补 Source-only/Overlay 等必要查询和正常问题。不得先大批重复同一未核验入口。
- 检查器通过只证明所选结构检查通过。它不会认证语义保持、未暴露确认、独立样本数或研究完成。缺少历史运行配置记录先查现有日志；不能为补元数据无条件重跑合法历史结果。
- 后续入口复用同一配置函数；新正式清单/表/运行可通过参数检查，完成后更新 contract 的 audit_inputs 指针，保留旧报告。不得为获得通过而放松固定范围或参数。

## 计量与质量修复
总 LLM = 更新输入/输出 + 查询 controller 输入/输出 + Reader 输入/输出。表格使用 contract.cost_components 的字段。按实际请求尝试去重引用日志；同一请求的重试是真实开销，不因逻辑请求 ID 相同被抹掉。缺 usage 保留 unknown；Embedding、初始构建、Judge 成本单列。
墙钟按实际阶段边界统计，嵌套的 retrieval 时间不能再次加进已经包含它的 prompt-build 时间。
质量按修改事实、未修改事实、旧值误用分开，并绑定 state/pre/post 角色。修改字段可以检查 CURRENT 视图，未修改事实检查合法完整记忆/上下文；旧值作为历史存在不自动算泄漏，被误当当前值才是错误。Source-only 的失效检查与其他方法的事件语义检查分别报告，不用一个布尔值排名。

Raw RAG/Notes 维护为既定必需交付，不是新增框架；用已有查询设计加最薄更新接口。遇难先解决，不自行 deferred。更改科学范围需用户明确指令；调整实现方式、执行顺序、修复常规错误不需逐项请示。
保留有效旧开发序列、初始构建与更新成本，扩量只补不足。Source-only/Overlay 与 Ours 配对，Delta Edit 不强制重新开发。正式数据用于修复则记录版本和暴露；原四个诊断题不改称独立确认。
PACKAGE 必须逐条指向 GOAL 完成条件的原始证据；表文件存在、命令成功、脚本检查通过、接受负结果，都不能替代缺失实验。首次检查失败修好后继续，不设置胜出门槛。
