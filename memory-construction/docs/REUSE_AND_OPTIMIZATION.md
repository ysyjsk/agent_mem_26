# 实验复用与 Ours 自主优化
协议 focused-maintenance-v4-20261015；执行修订 execution-recovery-20261016。本文件明确“完成对照”是先复用、只补缺口，不是重跑矩阵。整体方法、baseline 和公平协议不变。

## 1. 先建立复用清单，随即补缺
在 execution/reuse_inventory.csv 的现有审计起点上核对下一项所需证据，输出“已有结果—缺失结果—新增计算”。初次做一轮短审计，后续增量更新；不等待所有历史文件审完才跑明确缺失项，不建新管理平台。
每条记录写方法、阶段、数据/问题范围、原始路径、实际配置/语义版本、可复用部分、缺失部分、下一动作、重跑理由。候选复用在查清兼容性后才标确认。
动作包括 reuse、rescore、reaggregate、rerun_query、rerun_update、build_missing。直接引用结果、重评保存答案和重聚合日志都属于有效进展，不必重新调用模型。

按阶段判断兼容性：
- 构建：数据/表示、模型请求、生成配置、快照与合法缓存匹配即可复用。不相关分支、注释、路径或新增 Source-only 导致整体文件哈希变化，不是重构建理由。
- 更新：同一前置快照/合法缓存、修订及顺序、策略实际语义、模型请求和计时范围。哈希用于追溯；查代码差异是否真正影响该策略/案例，不要求整个文件哈希恒定。
- 查询/Reader：同一记忆、检索配置、问题、实际上下文/消息、模型/预算/thinking。仅查询策略改变就只补必要查询，不重做构建和更新。
- 评分：已有完整答案且仅评分变化时重评答案；需要模型 Judge 则单列评测成本，不能登记为新 Reader。
- 连续修订：前一轮快照改变会影响后续依赖，从最早受影响轮补必要后缀，不能拼接不同前缀的旧后缀。
- 计时：保留旧运行条件。硬件/服务负载实质变化才补少量代表配对校准，不全量重跑；旧有效重复完整保留，不取最快一次，不把同一 run 重复计样本。

每个重跑必须有具体原因：请求/数据/方法行为不兼容、必要缺项、失败修复或预定统计重复。换计划名、输出目录或代码文件哈希变化本身不是理由；不要求先重跑来证明能复用。

最初“新增十八单元”是旧部署时估计，已不作为本轮任务数量。Source-only 和开发序列已产生结果，先保留；当前具体缺口读取 execution/queue.json 和 docs/EXECUTION_RECOVERY.md。
已核实旧正式/消融和重复 Reader 请求带图，不能作冻结 text-only 质量证据；保留其更新快照与成本，只补受影响查询。开发序列 36 个请求无图不因此整体重跑，其他兼容性按原记录核对。Raw RAG/Notes 同负载维护、完整 Small 范围仍待补。
历史 derived_checks=false 先用保存源/事件/上下文复核：检查范围错误离线修正，真实错误才补受影响维护。别用单个布尔值宣称丢失或保持。

## 3. 初始记忆与表格
完整 Small 原则上三类初始记忆：Raw RAG、RAG+Notes、AgentRunbook-R。B3/Ours/Source-only/Overlay 从同一合法 AgentRunbook 快照分出独立维护分支，不另做完整 Event 抽取。已有轨迹分区可兼容则复用，扩库补缺；有全局依赖时核对其影响，不能假定逐轨迹独立。
修订前记忆、检索及实际 Reader 请求完全一致时，B3/Ours 等可共用正常 QA 测量并标 shared_reference，不算多个独立样本。引用原测量成本，不把保存答案伪装成新的零成本推理。修订后不同记忆需各自有效查询证据。
共享初始成本对各方法生命周期均计入，不是 Ours 免费。实际做了几次计算与每个方法部署一次的成本分开。
表格可分初始构建/正常 QA、维护＋查询两个部分，注明各自范围/配置。不同版本列不能拼出从未执行的生命周期。缺失 usage 保持 unknown；历史 AgentRunbook 构建有未知失败 usage，不填零。

## 4. 自主阅读与优化权限
执行 Codex 获准自主读论文原文、官方仓库/文档和本项目代码/失败样例，并选择实现当前方法内的候选，不必逐项请求批准。首表缺项优先，相关 CPU 阅读可并行准备，不让调研阻塞实测。
研究问题、baseline、开发数据和主指标固定；证据表示、局部依赖/回退、发布实现可演进。允许读 LightMem/Mem0 等资料，不把它们加入 baseline，不克隆整套新框架。
以一个实测瓶颈为问题，针对性读一至三篇方法/消融；没有能映射到当前代码的改法就回到实验，不持续泛搜。区分文献已有机制与本项目的组合/实现，不能换名冒充原创。
每个候选在 reports/ours_optimization.md 简记：瓶颈数字 → 来源链接/具体机制 → 改动函数及本项目新增之处 → 影响的计算 → 公平对照/风险 → 最小配对结果 → 保留/淘汰。自己的推理候选也允许，不强制每轮读论文。
每轮一个主要候选、一至两个因素。只补被改动影响的运行及关键质量回归，未变 baseline 复用；通用优化同时给适用对照，单列方法收益与共同工程收益。允许简化和选择性回退，不强制跑固定数量的 trick。

现有六轮：Ours 更新 LLM 为零、总 LLM 140111 tokens，其中 Reader 123082 tokens；按现有累计口径，查询占更新＋查询墙钟约 87.6%。这是成本诊断起点，不是新增结果。不要继续降低零调用，也不要转成无关的准确率搜索。
可自主选择：
- 检查维护后的当前证据、实体锚点、历史解释是否重复出现在 Event/Raw 上下文；减少重复表示，保留状态角色、最新值和原始可追溯证据。通用去重同等给 B3/Source-only，不能缩小其预算。
- 检查局部修订是否误触发整轨迹重抽取、无关 Notes/Embedding 更新；依据完整实际依赖/请求合法复用，不能使用“原句未在摘要中”的启发式。
- 源证据与旧动作解释冲突时，对必要 Event 使用已有 delta_guarded/重抽取回退；记录触发条件、比例与全部成本，以小额计算维持质量。
只有索引/发布确占主成本或 Small 扩量放大它时才优先优化。批处理/延后合并仍须遵守每轮可查询发布和固定查询负载，不能把工作移出计时边界。

可选阅读入口，不是必跑系统：
- [LightMem 原文](https://arxiv.org/html/2510.18866v1)：输入冗余、分组与在线/离线维护的成本划分。借鉴分析，不能照搬延迟更新来改变当前发布合同。
- [Mem0 原文](https://arxiv.org/html/2504.19413v1)：局部候选与 ADD/UPDATE/DELETE/NOOP 判断。可启发选择性回退，额外模型判断也计费。

## 5. 继续与收敛
复用清单 → 补缺首表 → 瓶颈/资料 → 一次必要改动 → 最小匹配实测 → 保留/淘汰 → 确认缺项/Small/写作。
必要检查通过就冻结并推进正式实验。可选主要候选全程最多两个，允许零个；无效则保留可靠 v13，不切换对象重启候选预算。
自主权限不覆盖修改答案、按结果换确认样本、关对照功能、隐藏失败或改正式计时边界。正式数据不能用于继续挑参数；版本和暴露记录保留。

## 补充：优化边界与研究收敛
1. 优化预算：首表后可选主要候选全程最多两个，默认跳过，切换对象不重置计数；必须有实际瓶颈、改动小、能立即配对验证且不延误正式实验。无收益则保留修正必要错误后的 v13。正式运行启动后不再尝试性能 trick，明确 bug 的必要修复除外。
2. 优化范围：对象始终是 Memory Maintenance Runtime。可减少更新后 Event/Raw 的冗余、过期内容、多余重生成/Embedding，以及改进必要局部回退；不得单独修改 Ours 的 Reader Prompt、输出/检索预算、Retriever 或评分获取优势。通用查询优化另行同等用于适用对照、单列收益，不作为本轮主线前置。
3. 数据隔离：Development 可选方法；Independent Confirmation 和 Full Small Final Evaluation 只验证冻结实现。确认/正式结果若用于方法修改，该样本标记已暴露和开发反馈，新独立确认使用未暴露样本。明确实现 bug 可修复并用新版本补受影响单元，但同一批结果不能继续宣称未暴露验证。正式轨迹、修订、问题、模型/评分清单在运行前固定。完整 Small 历史库可含开发轨迹，须区分历史覆盖与正式修订/问题的未暴露性。
4. 研究结束：不以 Ours 胜过 Source-only 或所有 baseline 为条件，也不把此胜负作为扩量关卡。必要正确性/公平性检查通过即进入完整 Small。完成既定正式表图、消融、质量/失败记录与正文后，可以得出优势成立或当前独特贡献不足两种结论；负结果完整保存并结束本轮，不无限优化强行制造正结果。
