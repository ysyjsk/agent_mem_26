# 局部记忆维护实验协议
版本：focused-maintenance-v4-20261015；执行修订：execution-ready-r2。以现有方法尽快形成可写作证据；不扩大为冷构建、持续新步骤或任意语义更新论文。

## 1. 方法与角色
| 论文名称 | 实现/更新行为 | 角色 |
|---|---|---|
| Raw RAG | 官方 rag_query_to_slice；修订对应原始切片和索引 | 公开低成本对照 |
| RAG+Notes | 官方 rag_query_to_slice_notes；更新源切片，必要时按原生成路径更新笔记 | 公开轻量经验对照 |
| AgentRunbook-R＋合法缓存 | 当前适配的 AgentRunbook-R/B3；触及分区经过原生成路径，保留完全一致请求/向量缓存 | 公开基础方法的强维护适配 |
| AgentRunbook-R＋Ours | v13 source_coalesced 核心；维护绑定状态位置的当前事件证据，支持范围外回退 | 主方法 |
| Source-only | 同 AgentRunbook-R 初始快照；更新 Raw State，受影响旧 Event 失效，不生成替代 Event | 关键消融，不是 Raw RAG 或新公开方法 |
| source_overlay | 同条件下追加有版本的当前证据，不合并旧补丁 | 已有合并机制消融 |
| delta_guarded | 使用已有源差异和旧记忆作局部模型编辑 | 已有编辑对照/必要修复备用 |

不把 B3 和 AgentRunbook-R 的这一个维护版本重复计作两种公开方法；不引用旧 workflow_b3 的数字代替当前 B3。
Source-only/Ours 之差包括事件可用性和事件级证据组织，称“当前证据维护”的整体效应。只有 overlay/coalesced 的匹配比较可解释合并操作的额外作用；笔记策略或其他因素不同的运行不能称单因素消融。
公开来源：https://github.com/xiaowu0162/LongMemEval-V2 。本研究的更新接口是适配扩展，不宣称官方原生支持历史修订。

## 2. 最小实现约束
- 复用 tools/run_agentrunbook_updates.py 与已有本地 adapter；在现有接口中增加最小策略，避免新框架/新模型服务。
- Source-only 更新 Raw State 的持久化和向量；只使按共同源位置/依赖规则判定受影响的 Event 不再参与当前事实检索。保存失效标记及源映射，未受影响事件/笔记保留。向量、词法补全、context 缓存和重载后的查询不得漏出失效事件。不要清空整个事件池制造对照劣势。
- 连续修订中，失效且未重建的 Event 不应在下一轮自动恢复有效；重建事件后才能恢复。缺失或过期索引应在发布前正确处理，计入成本。
- Source-only 不向 Event 注入 Ours 的当前证据块。原始源证据允许正常检索与共同补全。
- B3/Source-only/Ours/overlay 使用共同笔记规则：完全一致的实际生成请求可复用；依赖变化则按原路径生成。不能依靠整条原文不在摘要中来判定语义不相关。
- 默认基于 runner 哈希 a04bcf7c41e964bef6bf37cb8b2e799cf057bde018d99cc11e72434a200cc5d5 对应的已测 v13 行为；当前代码 a40d1564… 包含后加笔记规则。检查并以新版本显式关闭该规则，不覆盖历史文件；不要依赖哈希字符串假装恢复代码。
- Raw RAG/Notes 的官方 insert 不支持同 ID 修订；薄适配仅替换受影响轨迹的源与条目，保留合法缓存，必要时重建该分区，不能每次重建整个库。保持各公开方法的检索设计。
- 保存/加载、源映射与索引有效性应有针对性验证；仅验证本次新增失效、连续修订和更新入口，不扩建恢复系统。

## 3. 对齐条件
本地 Qwen3.5-9B controller/Reader、Qwen3-Embedding-8B；沿用当前 Reader 输出 2048、thinking 关闭、记忆上下文 12000，以及已工作的采样/事件请求设置。登记实际服务生效上限，不为新候选另降预算。
相同数据范围、修订顺序、问题、评分、Reader 和上下文预算；B3 与 Ours 的检索保持一致。公开 RAG 家族保留各自原检索结构；共同工程优化在适用方法中一致开放。
各方法在独立 memory/store 中运行。机制比较共享同一初始语义快照，各自携带合法历史进入下一轮；公开方法各自构建自己的记忆，不能借用 Ours 输出。
控制一轮 GPU 工作，记录运行顺序和失败。代表性案例预先指定并完成至少三次配对计时，可复用条件一致的有效重复；其他案例只因新增改动、异常或未解决的墙钟波动追加重复。

## 4. 数据和质量
首批使用已有两个域各三轮连续修订，直接补 Source-only。公开方法随后使用完全一致的修订/查询清单。
已有未调参确认按原版本/暴露历史先核对复用；仅对方法变化或覆盖缺项预选补充确认，依据完整性、修订类型与证据覆盖，不依据分数。登记轨迹数、修订次数、独立问题数和重复次数。
质量分为：原有正常问题；修改事实与未改邻近状态；动作结果/跨状态或工作流。定位明确的字段题保留为机制诊断，正常查询不能全部提供内部轨迹和状态 ID。问题与答案单独存放，检索不得接收 gold/评分元数据。
固定确定性评分适用于明确短答案；语义题统一人工/可用 Judge 评分并记录口径，不把关键词匹配当作完整语义验证。Judge 缺失时保存答案并继续可评分与成本实验，报告 pending，不阻断已授权本地工作。
保留失败、UNKNOWN、截断和过期解释影响；完整回答率与正确率分开。不强求一个小样本分数上涨，也不把相同分数表述为统计等价。

## 5. 成本口径
- 初始构建：单列。Ours 继承的初始 AgentRunbook 不是免费构建；不可把其更新成本与 Raw RAG 冷构建直接相比。
- 更新成本：实际生成、Embedding、条目/索引替换、持久化至可查询发布；源载入/克隆等排除项单列。
- 主要比较：更新 LLM 输入＋输出 tokens，以及固定查询负载下的更新＋查询总 LLM tokens；并列真实发布时间和查询墙钟。
- 查询成本包含检索 controller 与 Reader；Embedding calls/vectors/tokens 单列，不混称 LLM tokens。只计算本次实际发生的请求；合法缓存命中不登记为新请求，实际重试计入成本，不重复累计同一请求或继承历史日志。
- 总生命周期在有可比初始成本时报告 C_initial + ΣC_update + ΣC_query。只报告维护总计时必须明确排除初始成本，固定查询/更新比例。
- 零更新 LLM 不等于零成本或自动优于 Raw RAG。Source-only/Ours 接近时看证据组织是否降低实际查询成本或保持有价值的质量。
- 每行带方法版本、manifest、原始结果路径、评分状态与失败数。历史不同配置只作背景；不得拼成同一最终版本。

## 6. 决策与冻结
先用已有开发输入判断方法和对照差异，再做最多一个主要候选的定向修改。每轮明确要减少的计算及质量风险。
若 Ours 相对 B3 有可重复降本，并在 Source-only/公开轻量对照前体现质量或总体成本的实用取舍，固定实现后完成确认、表图与正文。
若 Source-only 持平或更优，优先简化方法或修复具体事件证据问题；不能把无增益组件写为核心创新。若所有轻量方法同质更便宜，继续本范围内有依据的改进并真实记录，不能仅凭 B3 大幅降本宣布论文完成。
不新增 baseline、不扩大到其他构建问题来回避当前比较；已有负结果保留，写作围绕最终得到支持的范围。

## 7. 运行准入和两阶段 Manifest
Source-only 仅做四组必要一致性检查，不扩建恢复系统：
1. 单次修改后，受影响旧 Event 不能经向量、词法补全、上下文/Reader 缓存被作为当前事实召回；同时新版 Raw State 必须仍可正常检索。
2. 同位置连续修订后，未重建的失效 Event 不自动复活；其他未改状态保留。
3. 未受影响 Event、Notes 和其向量内容保留。允许索引必要的行重排，不要求整个索引文件字节不变。受影响 Notes 按共同合法规则处理；Source-only 不等于保证零 LLM。
4. 保存并用实际评测入口重新加载后，上述行为一致；不能只在 updater 的临时对象里设置标记。加入未修改状态的对照检查。

首个真实修订/查询确认这些行为后跑六轮开发表。首轮对 B3 的目标是更低成本且无明确系统性质量退化，不要求 QA 提升。Source-only 不能被关闭正常 raw retrieval、共同补全或给更小预算。若差异只存在特定问题类型，分项说明；不能靠按结果换问题制造收益。

Manifest 使用现有 JSON 即可，不建设新管理平台：
- 数据清单先冻结：阶段、域、完整历史 trajectory IDs、revision IDs 与顺序/内容哈希、question IDs 与问题/答案/评分文件哈希、证据覆盖、选择理由、既往调参/查看记录、固定每次更新的查询负载、代表重复案例及次数、顺序安排。gold 与评分元数据不传入检索器。
- 运行清单后冻结：引用数据清单哈希；Git commit 加关键代码/未提交补丁哈希（仅 commit 不够）；实际模型/服务与请求配置、Reader/thinking/输出预算、方法策略、初始快照与构建配置、缓存继承规则、计时边界、评分配置、输出目录。无密钥。
- 数据选择发生在查看其确认结果之前；代码/配置冻结发生在该阶段正式执行之前。待填/计划清单不可标 frozen。
- 发现 bug 可修复，使用新版本、新清单和新输出；旧数据保留，重新运行受影响单元。利用确认表现选择方法后，这批算已暴露；再确认须预先选剩余未调参数据，否则明确不再是独立确认，不据分数挑选。
- Ours 与所有对照采用同一修订/问题集合和固定评分。数据完整性排除预先记录，不按胜负筛选结果。

完整 Small 的扩量条件：准入检查通过；开发/独立确认中相对 B3 有可重复成本下降；没有未修复的系统性功能退化；Source-only/轻量对照下的方法价值能由质量、检索/状态归属或相同质量下的总成本解释。小样本相同分数不宣称统计等价。若尚不支持，继续当前范围的针对性开发，不把试验扩大当作修复。

## 8. 完整 Small 与交付口径
正式主实验是完整 Small 历史库＋提前固定的局部修订与查询集合，仍为 text-only/adapted；不是官方全部问题、多模态或任意更新的复现承诺。从现有官方 Small 映射确认历史库 IDs，完整轨迹不能随机截短。记录实际历史规模、修订数、独立问题数、重复次数和覆盖。
各架构的初始记忆只构建一次并单列成本；B3/Source-only/Ours/Overlay/Delta Edit 可从同一合法 AgentRunbook 初始快照分出独立分支，连续修订各自继承自己的结果。Raw RAG/Notes 各用自己的初始记忆。所有架构共享的通用优化和缓存政策一致；不得用其他方法本轮答案或新生成记忆充作自己的免费缓存。
先估算全库初始构建时间/资源，保留有效已建分区和必要断点，随后执行同负载四行主表。Source-only/Overlay 在相同预选核心修订子集比较；Delta Edit 优先复用历史，不兼容则分版本辅助展示，不为凑表重开发或全量执行。支持范围外的改动使用既有回退并记录比例/成本，不能只隐藏回退案例。
最终 public_main.csv 明确正式阶段；开发首表放 dev/。每行除来源/版本外包括历史规模、修订/独立问题/重复数、初始成本引用、更新 input/output/calls、publish wall、query input/output/calls/wall、维护总计、embedding、有效回答/质量分项/评分状态/失败数。缺失记 null/pending，不填 0；生命周期成本只在初始成本可比时给出。
连续曲线和核心消融可以使用完整历史上的固定子集，但范围必须写清。复用已测结果时登记适用范围和条件；不同语义/配置的旧结果只作历史，不强行拼接。
