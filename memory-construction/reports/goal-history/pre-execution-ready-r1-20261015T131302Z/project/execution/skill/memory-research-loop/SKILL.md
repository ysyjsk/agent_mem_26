当前用户优先级：**先有基础 baseline 和我们方法的真实对比，再按数字优化，MemForest 后续补。** 不把全部外部复现或完善执行基础设施当成开始测量的条件。

## 一轮执行闭环

**假设 → 必要代码改动 → 真实配对运行 → 原始记录与表 → 解释差距 → 立即执行下一项。**

- `queue.json` 的 active tasks 控制当前依赖，backlog 不阻塞首表。只有验收产物有真实数字且已核对才标 done；CLI 返回 0、smoke 或 replay 不算。
- 第一张表允许一致且明确的 construction_kernel 范围，输出耗时、调用、输入/输出 tokens、快照检查和失败数；不能叫端到端 Freshness。然后补完整计时和强 B3。
- B0/Ours 使用相同窗口、checkpoint、视图、模型和预算，独立方法 store/cache。Ours 可复用自己的有效计算，不能读取 B0 的回放结果冒充加速。当前机制未齐全叫 Ours-dev，不叫 Full。
- 每个 checkpoint 即时保存测量；失败留档，其他可执行窗口继续。先补这一最小持久化，不要求完整通用恢复后才跑。
- 缺少官方 Judge 时照常做构建/性能/Reader 与待评答案，质量填 not_evaluated。不能凭离线一致性代替官方 QA，不能把文本开发子集叫完整多模态 benchmark。
- 每轮只记必要证据：baseline/候选 run、改动、指标、错误样本、保留/回退理由与下一项。未改善则定位重算范围、上下文、调用粒度、索引和排队，继续有效修复；保留负结果。
- 只在开发集选参数；强 B3 获得同等预算和合理优化，正式集冻结后评测。

## 报错后继续，外围卡点绕出主线

导入失败先核对已验证解释器；OOM 先查作业归属、重复加载、batch/in-flight 和上下文峰值；模型输出错误修复解析或提示词，不静默替换成启发式/离线后端冒充实测。未解决的核心正确性错误必须修复。

准备工作约 20 分钟无新增可运行性或数字时，判断它是否是下一张表的必要依赖。非必要的全量下载、外部适配立即 deferred，回到小数据主线；必要问题缩小复现、改变假设再试。该检查点不是有效实验的硬超时。同一故障累计 3 次触发诊断升级，不代表退出项目。

不要机械重跑相同命令；不要创建多个重复下载或模型服务；不要杀不明归属进程。用户已授权的必要常规修复直接做。GPU 正在跑主线有效实验时等待其进度，并完成直接相关 CPU 工作，不借机扩大 MemForest 支线。

耗时尝试可直接使用现有 `scripts/research_loop.py --root <root> run --task <id> --hypothesis '变化与预期' --timeout <秒> --resource cpu|gpu -- <命令>`。它只监督自己的进程并保存日志，不推理修复；GPU 启动前需另外确认现有非受管作业。真实实验进度与监督心跳分开。不要在命令行写密钥。

## 持续性与交接

进度消息说明“离下一张表还差哪个动作”，然后马上执行。只有用户暂停、宿主预算限制、实际目标完成，或所有剩余必要工作确需外部输入时才按宿主规则结束；不把已列待办当完成。

Skill、AGENTS 和 GOAL.md 不会自动唤醒空闲会话。支持原生 Goal 时延续/设置项目 GOAL.md 中的目标；没有该能力时当前轮内继续执行并保存精确恢复命令，不声称已启用自动续跑。不启动无穷自调用或另一个竞争执行器。

当前正在运行的 VS Code 会话需读取 `EXECUTION_UPDATE.md` 并写真实 v4 回执；旧 v3 回执不能代表采用本次优先级。回执本身不是交付，写完立即推进首表。
