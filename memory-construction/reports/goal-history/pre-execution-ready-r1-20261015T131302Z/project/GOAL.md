# Goal：局部记忆维护的方法、论文实验与写作交付

版本：focused-maintenance-v4-20261015。这是执行计划版本，算法起点仍为 v13，不命名为已验证的新算法。

## 总目标

在现有本地 AgentRunbook-R 链路和完整轨迹数据上，完成源证据驱动的局部记忆维护方法及可直接写作的实验包：公开比较固定 Raw RAG、RAG+Notes、AgentRunbook-R（统一适配与合法缓存）和 Ours；关键机制比较固定 B3、Source-only、Ours，并复用 overlay→coalesced 解释合并作用。以更新及更新＋查询的真实成本为优化目标，以正常问题、修改事实和动作/跨状态问题为质量约束。先补 Source-only，再补同负载公开 baseline、未调参确认和必要消融，实验期间同步写方法与实验章节；出现失败或优势不足时在现有方法内进行有依据的局部修复或简化，直到形成经验证的最终版本、完整必要表图、逐题记录与可复现稿件。暂停 Codex、AgentRunbook-C、MemForest、LightMem、新数据集和冷构建/自然增长新路线；不以零调用、表格数量或预定胜出代替实际效果。

## 当前选定范围
- 研究问题：已有 Agent 记忆发生局部源证据修订时，减少重复生成与发布成本，维持所测下游可用性。
- 起点：v13 source_coalesced 的已验证核心；不默认加入“完整旧/新源行不在笔记中就复用”的追加规则。笔记按共同合法缓存和真实依赖更新。
- Source-only 是同一记忆架构中的消融，不是新的公开 baseline，也不等同于从零构建的 Raw RAG。
- B3 是当前 AgentRunbook-R 的缓存维护对照，不是旧 workflow_b3。主表中不把它重复算作额外公开方法。
- Source-only→Ours 检验事件级当前证据维护的整体价值；overlay→coalesced 才隔离追加与合并的差别。
- 初始构建、更新、查询分别计量。主要目标是成本，不把准确率小样本涨分作为搜索方向。

## 完成条件
1. 最终方法、模型/Reader/检索配置、数据清单与评分口径固定；实现行为与论文方法一致。
2. 公开方法四行主表和 B3/Source-only/Ours 机制比较完成，所有行具有原始路径、实际成本、质量分项、失败与版本记录。
3. 已有连续序列和成本重复被正确复用或补齐；增加未调参轨迹确认及覆盖动作结果/跨状态关系的问题，不能只有给定轨迹编号的字段查找。
4. 主表、核心消融、连续修订成本/证据大小图、确认结果、方法/实验/局限章节和复现入口交付；每个主张可追到具体结果。
5. 明确说明相对各对照的真实收益与取舍。无证据的优越性不写入论文；不把所有候选跑完或只有负结果归档当作研究目标完成。

## 自主迭代
固定问题、baseline 和主指标；局部实现可演进。每次只推进一个主要候选、改动一至两个因素，依据成本分解和失败样例行动。Source-only 与 Ours 持平时，先定位检索/事件证据是否产生作用；可以采用更简单的版本或缩小主张，不预设 Coalescing 必须胜出。同类改动连续两轮无改善，改查另一个明确瓶颈，不扩大外部适配或重做环境。核心优势仍不足时继续本范围内有依据的改进，不宣布论文已就绪。
