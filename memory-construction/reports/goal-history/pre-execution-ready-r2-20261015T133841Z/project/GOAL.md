# Goal：固定范围内完成有效方法、完整实验与论文稿件
协议：focused-maintenance-v4-20261015；执行修订：execution-ready-r1。算法起点仍为 v13，不因此命名新算法。

## 总目标
在现有本地 text-only/adapted AgentRunbook-R 链路上，完成已批准的局部记忆维护方法与可写论文的实验包：以更新及固定查询负载下的总 tokens、发布时间为主要目标，以正常问题、修改事实和动作/跨状态问题的可用质量为约束。固定 Raw RAG、RAG+Notes、AgentRunbook-R/B3、Ours 四行公开比较，完成 B3/Source-only/Ours 机制比较、Overlay/Delta Edit 核心消融、两域连续修订、未调参确认和代表案例至少三次配对计时；首轮及独立确认支持后，完成完整 Small 历史库上的固定修订与查询主实验。复用合法初始快照和有效旧结果，以真实记录持续做必要局部修复，遇到失败不退回环境重建或外部框架适配。同步交付最终版本、完整清单、逐题答案、成本质量表图、方法与实验正文和实际复现命令；只有结果支持明确成本—质量价值且必要交付完成才标记研究目标完成，不以文档齐全、单次报错、零调用或预设胜出作为终点。

## 范围与判断
- 整体 Methodology、baseline 和主指标已固定；现有方法内的必要实现修复、证据组织、索引与回退调整允许继续。一次一个主要候选、一至两个因素，立即实测。
- Ours 从已验证 v13 source_coalesced 核心出发，关闭“完整源行不在笔记中即复用”追加启发式。共同合法缓存、必要 Notes 生成及回退对所有适用方法一致。
- Source-only 不是 Raw RAG：共享同一初始 AgentRunbook 记忆，保留未受影响 Event/Notes，可正常检索更新后的 Raw State，只不维护受影响 Event 的当前证据。
- B3 是当前 AgentRunbook-R 的强维护适配，与主表 AgentRunbook-R 是同一行，不能混用旧 workflow_b3。
- Source-only→Ours 解释整体事件证据维护；Overlay→Coalesced 解释合并增益。
- 主要目标是降本且保持可用性，不要求准确率上涨；检查更新＋查询，避免成本转移。对 Source-only/公开轻量方法应有可解释的质量或总成本取舍，不能只凭 B3 的大幅降本断言贡献成立。
- 不增加 Codex、AgentRunbook-C、MemForest、LightMem 或新数据集；不转向冷构建/自然增长新方法。

## 完成条件
1. Source-only、共同笔记规则和公开更新入口经必要检查及真实运行；实现、配置和论文描述一致。
2. 已有两域各三轮开发比较、四行公开对照、独立确认均有可追溯结果。正式扩量前按协议的两阶段 Manifest 固定数据与最终实现。
3. 完整 Small 历史库的固定维护负载完成，主表四行齐全；Source-only/Overlay/Delta Edit 在预先固定的同一核心修订子集比较，不要求每个消融重跑全部历史问答。
4. 连续修订成本/证据大小、质量分项、总成本与失败记录齐全；代表案例至少三次配对计时，可复用语义、配置和运行条件相符的已有重复。
5. paper/manuscript.md、paper/reproduction.md 和最终表图完成；主张可追到原始运行，不把不同版本拼成一个从未实测的方法。
6. 完整 Small 指完整历史库＋固定修订/问题集合，不等于官方原生全量多模态 QA。小表完成不能代替正式主实验完成。

## 继续工作的规则
首轮和确认的进入条件见实验协议；未满足时留在开发阶段查清一个主要原因并修复，不提前扩量。不理想的结果保留，不能按得分换案例。连续两轮同类改动无改善，换查有证据的瓶颈或简化无效组件，仍限定在当前方法。必要实验因外部条件暂缺时，先完成可执行工作并保留具体恢复点，不把报告写完等同于研究完成。
