Costs match query IDs to actual controller/embedding records. Historical Reader SDK retry allowance was not accompanied by a per-attempt transport ledger; displayed Reader usage is the recorded returned usage, not a claim to recover invisible retry costs. New formal transport disables those retries uniformly.

RAG+Notes round1 made two calls/domain: a new note request and JSON-format repair. The inherited5-trajectory snapshot contains matching request text but no recorded finish_reason or thinking value, so its old responses were not silently re-keyed as confirmed stop/thinking-off responses. Rounds2-3 each reuse both newly recorded responses and make zero note calls. Thus the round1 note cost is a provenance/cache-start transition, not evidence that literal source corrections intrinsically require note regeneration. The main table retains that actual cost; rounds2_3_component.csv isolates the later warm-cache phase without dropping round1 from lifecycle accounting. Formal full-history results are separately measured.

Generated event/Notes checks are exported separately; their pending semantic labels are not quality passes. Fixed answers and failures are retained. Repeated corrections do not increase independent target count.
