# Method discovery: matched local updates (work in progress)

This is text-only/adapted development evidence, not native Small or official Judge quality. The method is not frozen. The primary cost measure was selected before running: total LLM input plus output tokens; publication latency and Embedding work are reported independently.

## Mechanism and credible control

A request cache cannot reuse a changed request even if most of its page text is unchanged. Joint extraction makes this worse at group boundaries: two changed transitions can invalidate two groups and regenerate four event outputs. An event-level dependency cache separates the outputs, but when both methods already recompute exactly the same two events, it does not reduce their costly page reading or complete output generation.

The old enterprise comparison confounded this effect with a changed request preparation policy. A recent expanded20 snapshot also lacked full request records, so reconstructing an exact request cache from it was impossible. These diagnostics are retained, not used as method evidence. Current shared starting snapshots re-prepare only the four selected partitions under one common prompt/input/budget policy. Actual exact requests are preserved, and event dependency keys are saved when outputs are constructed. Re-keying arbitrary old event outputs under a new configuration is prohibited. After loading persisted caches, both domain snapshots pass a no-change B3 rebuild with zero real LLM or vector requests.

## Current narrow candidate

The initial observation-model design below is retained as development history. V11 has superseded its additive branch: explicit appended facts are merged deterministically, which the zero-LLM comparator showed is sufficient for these cases. Literal replacements use old event memory, explicitly separated obsolete/current source evidence and exact neighboring-entity lines. A narrow numeric/value-literal absence check avoids rewriting a narrative that never asserted the old value; the current observation is instead attached to its exact pre/post-state. When an old assertion is present, the model emits validated literal edits and preserves all other substrings. Invalid edits use the original extraction for the affected event only, and all fallback cost is counted. Other note changes retain the original note extraction; only strict additive workflow intent uses direct procedure augmentation.

This selective work allocation, not a claim that the LLM must paraphrase source additions or that DAG bookkeeping alone is useful, is the current hypothesis. The literal absence check is limited and does not certify paraphrase-level nondependence; generated-memory and targeted Reader checks remain necessary. Full-prefix action/length dependencies still invalidate growth as before. No continuous-growth benefit is claimed.

The updater compares current source states with the stored trajectory. For a local additive change it supplies the existing event fields, task and local action context, and the exact added evidence to the same Controller. The model emits one short observation per changed source, rather than one complete event per affected transition. A deterministic dependency mapping attaches that observation to all affected events, explicitly identifying whether it modifies their pre- or post-state. Existing fields remain unchanged prefixes. For additive workflow clarification, the same generated observation can update the procedure note as recorded intent, while preserving the previous note and hint. Source references and independent exact-vector caches are retained; all changed vectors, merges, serialization and reload verification are included in update publication cost. Unsupported/global changes or invalid edit output use the existing extraction path, with fallback costs retained.

This is a hypothesis about local, evidence-backed updates, not a claim that simple append logic safely handles all corrections. Literal replacement edits remain a separate, not-yet-validated path. Growth changes global action/length dependencies and is not claimed optimized.

## Necessary quality limits

The existing fixed workload uses four complete trajectories, two per domain, in five-trajectory shared libraries; the other histories are retained unchanged. Each trajectory has a state and a workflow revision, covering joint-group interiors and boundaries. All eight changes append explicit status or workflow clarification strings. They are useful for detecting missed propagation, but cannot establish revocation or replacement correctness.

Check generated overview/state_transition and note_text, excluding raw states and copied thought metadata. Preserve source/event coverage; inspect before/after generated records, including whether an observed correction is wrongly described as an action outcome. Keep fixed Reader settings (Qwen3.5-9B,2048 output,thinking off,12000 context,chunking,tokenizer reuse,lexical backfill,exact query embedding reuse). Do not search query parameters.

The first literal-edit candidate saved input tokens but rewrote whole paragraphs, dropping old details and adding unsupported causality. It was rejected despite lexical checks passing. A source-observation form avoids rewriting unchanged fields. A loose workflow regex also gave false positives from unrelated note headings; the current necessary check requires verification and ordering in the same sentence/bullet. These repairs and all negative attempts are recorded in the raw runs and optimization log.

## Predeclared v6 replacement / trivial-comparator screen

Primary measure remains total LLM input+output tokens, with publication wall, vector work and failures reported. Two fixed manifests in `configs/method_*_replacement.json` alter an existing visible Title/count at a single state, not an appended status sentence. Selection is based on preexisting generated facts, distinct form/list pages and group boundary/interior; the original four trajectories are unchanged. These are controlled counterfactual source corrections, not official QA amendments. Actions, goal and neighboring states remain unchanged: attempted values must not override the revised observation, nor may the correction be propagated to an untouched neighboring state. Predeclared generated-field rules are necessary checks only, followed by direct semantic review.

Hypothesis: literal field editing can avoid full-page processing and retain unrelated memory while retracting a stale local assertion. Strong B3's exact request cache cannot reuse the altered groups. A failure of old-fact removal or state roles rejects the candidate regardless of savings. The two pairs decide whether to retain the current literal-edit prompt or change its grounding before any method freeze. In parallel experiment design (but sequential GPU execution), two existing additive cases receive a deterministic `source_append` comparator. It uses no LLM for copying the exact added fact and shares dependency propagation, notes/index publication. If this matches quality at lower cost, the model-generated additive observation is not a contribution and must be removed or reserved for genuinely semantic updates. Non-additive changes are never handled by naive appending; they fall back to normal extraction.
