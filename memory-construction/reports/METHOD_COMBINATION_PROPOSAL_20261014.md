## 1. 本轮目的

通过可组合的小改动，提高当前开发集上的质量与构建效率，尽快形成能够扩量的最佳版本。文献作为可借鉴的方法库，不因某个宏观概念已有工作就否定组合方案。允许工程 trick、启发式和表示调整；贡献最终围绕真实结果组织。

推荐组合是：**结构化原始证据 + 多步联合抽取 + 稳定片段复用 + 一次按需补证**。先实现最直接的两项，按结果决定是否叠加后两项，不要求一次完成整个系统。

|---|---:|---:|

### 2.2 已确认：关键词行压缩会丢掉答案与结构

C 的 `_compact_evidence_tree` 主要保留关键词命中行及前一行，最多选 20 个命中位置，再按字符上限截断。它没有系统保留父子、字段—值、兄弟列表和动作结果关系。

Apple Watch 题 `ad903be2`：baseline 送入 Reader 的上下文含 `2 days` 且答对；C 的最终上下文不再含该文字，并回答 UNKNOWN。这个实例支持优先改进证据保留；它不证明所有错误都由压缩造成。

蓝色回复提示条题 `11dac74b`：AgentRunbook-R 的最终上下文已经含 `View all comments`，仍然答错。这里应重点检查文字是否与正确动作、提示区域关联，而非一味增加召回量。

来源：相应 `*-agentrunbook-r-reader2048-v1`、`*-agentrunbook-r-optC-v1` 的 `per_question.jsonl`，以及 adapted `memory_modules/agentrunbook_r.py` 的 `_compact_evidence_tree`。

### 2.3 已确认：客户端并发还没有形成模型批处理

B 候选修改客户端事件请求并发数；`tools/local_openai_server.py` 仍在 `with self.lock` 内执行单个 `backend.complete(request)`。因此不能把它当作真实生成批处理。

优先通过多步联合抽取减少请求次数；不把部署新推理框架当作下一张表的前置条件。

## 3. 从文献中借用的具体做法

| 来源 | 借用什么 | 在本项目中的落地 |
|---|---|---|
| [SimpleMem](https://arxiv.org/html/2601.02553v1) | 结合稠密、词法与结构信息检索 | 现有向量召回加 BM25，保留页面、动作与字段结构 |
| [LazyMem](https://arxiv.org/html/2607.22690v1) | 召回后扩展相邻上下文，合并重叠窗口 | 合并重复状态片段，围绕动作与命中节点补证；暂不训练其压缩模型 |
| [LightMem](https://arxiv.org/html/2510.18866v1) | 先分组，再调用模型构建记忆，减少过细粒度调用 | 同一轨迹内相邻动作联合抽取，共享页面背景 |
| [Adaptive-RAG](https://aclanthology.org/2024.naacl-long.389/) | 按问题需求分配处理量 | 依据当前证据缺口，最多追加一次局部检索和回答；先用规则 |

上述论文结果不直接外推到 LongMemEval-V2。这里采用的是可借鉴机制，下面的 AXTree 分块、动作分组与缓存方案是针对当前项目的实现建议。

## 4. 推荐实验顺序

### P0：共同修复超长证据装入

目标：在当前预算内，Reader 不再因单个文本块过大而只收到标题。

- 复用已保存 memory_state，不重跑构建。
- 超长文本在送入最终裁剪器前拆成有来源标识的较小块；标题与至少一段实际证据一起装入。
- 不因为一个块装不下就丢掉后面所有可用块；按预算明确选择可装入的证据。
- 先用简单、统一的分块策略修复全部方法；下面 E1 的结构化策略再作为候选比较。
- 重跑同一 8 题，记录实际上下文 tokens、逐题答案与评分。

产出：修复后的 baseline 表。这个共同修复不包装为 Ours 的独有收益。

### E1：结构化分块 + 混合召回

目标：让关键字段、列表关系和动作结果进入 Reader，同时减少无关页面文本。

最小实现：
1. 按 AXTree 表格、列表、表单、提示区域或有界子树切块，初始目标可设为约 512–1024 tokens；大块继续按子结构拆分。
2. 给块保留轨迹 ID、状态位置、页面标题/URL、父节点路径及必要的前序动作。只规范化确定无语义的临时标识，不删除数字、顺序、字段值或时间等信息。
3. 先复用现有 dense 召回，并对原始证据块建立 CPU BM25 索引；使用简单 RRF 合并，不新增大型 reranker。
4. 根据问题与命中位置补齐必要结构：字段题带值与所属标题，序数/枚举题带同组兄弟项与顺序，动作后状态题带前后状态和动作目标。
5. 同一状态、相邻重叠区间合并，按既定 token 预算装入。不要硬编码题号或标准答案。

先仅改变检索和上下文组织，保持 Reader 一致。证据位置用于开发诊断，不作为运行时的答案提示。

产出：E1 相对共同修复后 RAG/AgentRunbook-R 的质量、查询耗时与 tokens。不要先对全部历史做额外 LLM 摘要。

### E2：多步联合抽取，直接减少昂贵请求

目标：保持逐事件输出关系，将多个独立请求合并成一个有界请求。

- 同一轨迹内每 2 或 4 个相邻状态转移为一组。页面/任务边界、轨迹结束、输入预算达到上限时提前结束分组。
- 组内共享背景只输入一次；每步保留动作、状态对应关系和原文引用。
- 一次输出带独立 event_id 的事件数组，不把多步压成一条无法追溯的泛化总结。
- 使用统一输出 schema；某组解析失败时，仅修复或拆分该组，并记录额外成本。
- 第一次实验先改变分组粒度，不同时修改检索、Reader 或去重阈值。比较 2 步与 4 步后保留较好的版本。

调度估算：当前 91 状态、10 轨迹，若每相邻状态产生一个事件，则共 81 个事件抽取请求；按已记录轨迹长度，每 4 步一组约 26 个请求。此数不含轨迹 Notes、修复与回退，也不是实际加速比。生成量可能不同比例下降，以实测墙钟时间为准。

产出：组数、请求数、输入/输出 tokens、构建至可查询耗时、逐题质量与回退量。

### E2b：在较优分组上加入稳定片段复用和状态差分

目标：减少同一页面被反复读取、抽取和 embedding 的成本。

- 保存一份可回查的页面/子树基底，再记录新增、删除、修改和必要的顺序变化。
- 给模型输入动作相关变化及其必要祖先、字段值和邻近上下文，避免只给无法解释的裸 diff。
- 相同内容但不同动作、时间或来源仍保留不同事件引用；可以共享文本/向量，不直接删除这些经历。
- 缓存键包含实际输入内容、必要上下文和模型/提示词配置；来源更新时，仅失效相关抽取组与派生笔记。
- 先使用现有依赖记录，不为此重新建设通用 DAG 引擎。

产出：在相同分组粒度下，相对 E2 的输入 tokens、embedding 工作量、总耗时与质量变化。

### E3：一次按需补证

目标：提高困难题准确率，而非让所有题都承担多轮成本。

- 首轮正常回答。触发条件先选可操作的少量规则：UNKNOWN、无法定位支持答案的证据、序数/枚举问题缺少完整相关列表。
- 仅展开相关父节点、相邻状态或对应动作片段；最多追加一次 Reader 调用。
- 已有标准 Reader 格式可保留，在可行时附带源位置；若修改 Reader 提示词，则所有比较组使用同一基础提示词。
- 不新增独立 Judge 来决定每道题是否回退；使用现有数据结构与轻量规则。
- 将追加检索、构建和 Reader 成本计入该查询，分别报告首次回答与回退后结果。

产出：触发率、修复题数、损失题数、最终准确率、平均与尾部查询成本。

## 5. 最小实验矩阵与组合选择

| 组别 | 改动 | 首要目的 |
|---|---|---|
| Baselines-fixed | 全部方法采用共同装入修复 | 建立有效比较起点 |
| E1 | 结构化分块与混合召回 | 改善证据利用 |
| E2-k2 / E2-k4 | 联合抽取粒度 2 / 4 | 降低构建请求开销 |
| E2b | 最佳分组加稳定片段/差分复用 | 降低重复输入与索引成本 |
| E3 | 最佳组合加一次按需补证 | 改善困难题质量 |

这些是可组合组件，不要求弱候选进入最终方法。先筛出有效组合，再补移除关键组件的消融。通用优化同样提供给 B3；若比较依赖机制，B3/Ours 必须使用相同分组、表示和模型设置。

每轮复用兼容产物，仅改动构建逻辑的版本需要重建。首轮各跑一次筛选，有希望的候选再重复，随后扩到 20–40 道证据覆盖明确的题。开发集用于选择方案，扩量时保留新加入问题的独立结果。

质量和成本一起决定保留哪个版本。优先目标是达到修复后 AgentRunbook-R 的质量，同时明显降低构建成本；若质量提高但成本增加，则单列取舍，不混称全面改善。
