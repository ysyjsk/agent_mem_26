# 当前 Goal：集中改进方法，尽快产出有价值的论文结果
版本：2026-10-15 / focused-method-v3
项目：/data/predator/ly/agent-memory-construction-2026-10-12/memory-construction
本版取代旧版“先接齐外部框架”的排序；既有真实结果继续保留。

## 目标
在现有可运行实验链路上，持续优化或替换 Agent Memory Construction 的当前方法，在保持记忆质量和下游可用性的条件下，取得相对相关强对照可重复的主要成本收益，然后完成支撑这一明确贡献的必要论文实验、表图、方法与实验章节和复现入口。主要优化实际 LLM 总 tokens、模型工作和更新到可查询发布的耗时；质量是约束。把资源集中在能改善方法或决定方法取舍的真实运行，不把基线数量、框架完整度和报告数量作为目标。不锁定当前 Ours、DAG 或模型编辑；无效组件及时删除，有依据的新机制主动实现。

## 当前优先级
1. 复用已完成的可信快照、缓存核对和 v11/v12 产物，仅补最新方法缺失的正常检索验证。普通固定题回归与“修改后的事实是否答对”分别记录。
2. 从 source_overlay 这个便宜起点出发，优先验证两种小改动：同一来源/状态的多次修订合并成当前有效证据，避免反复追加过期补丁；只有旧解释确实失效时才调用模型局部修复。它们是待验证候选，不是预定贡献；简单覆盖足够就不增加模型分支。
3. 若模型处理仍是主要成本，再选一个瓶颈对应的优化：相邻事件共享变更处理、精确重复片段复用、仅输出必要修改。每次只试一至两个因素，不同时铺开所有 trick。
4. 主对照使用已经可运行的 AgentRunbook-R 及其合理优化后的强 B3，复用 Raw RAG/RAG+Notes 作简单外部参照。MemForest、LightMem 和其他新框架均后移。官方 Codex/AgentRunbook-C 只有现成入口与模型访问能直接使用时才补充，不新建兼容层、不阻塞主线。已运行作业由原执行者在可保存边界安排，不强杀、不丢结果。
5. 先得到当前方法的成本—质量优势，再一次性确定必要正式实验清单并执行，不为“更全”持续加项目。

## 每轮如何推进
维护一个可复现的当前最佳版本和一个主要候选。按“最大差距 → 原因 → 最小改动 → 真实配对 → 保留/淘汰 → 下一项”循环。允许开发集上的提示词、表示、缓存和执行策略优化，但每个 trick 必须说明减少什么计算、为何不损伤关键事实、是否已被强基线覆盖。
连续两轮同类微调没有改善，就改变假设或机制，不继续堆同类参数；这不是结束总任务的条件。tokens 降但耗时不降，查输出/重试/等待；回答退化，查检索/版本/状态归属；简单方法同质量更便宜，删掉无用抽取和维护工作。针对需要解释的差距短查文献/官方代码后立即回到实现。
常规报错自主修复，保留完成项并继续；不重做 P0、不建设通用恢复平台。每轮必须新增真实数字或消除当前运行阻塞，不能用更新计划替代推进。

## 最小论文证据包与收敛
- 一张主结果表：固定任务与完整所需历史、同口径模型和资源下，当前方法对相关强对照的 tokens、发布耗时、质量、失败。冷构建、更新、查询分列。
- 一张关键消融表：只移除最终核心机制，解释收益来源；零 LLM 覆盖若不是最终方法则作为必要简单对照。
- 一次独立确认：用未参与调参的新案例确认成本与质量方向；关键成本配对做三次重复，匹配旧重复可复用。
- 仅在最终机制涉及持续维护时增加一条累计成本/记忆长度曲线，确认查询或版本积累没有抵消收益。
- 按最终贡献确定两域评测、样本规模及必要边界；正式清单在查看新测试结果前固定。图表与论文描述忠实反映支持范围，不把几个字段修正推广成全部构建加速。

出现稳定且有实际意义的收益后就收敛、扩量并写作，不追求所有指标第一；若独立确认出现实质退化，保留结果，针对原因回到开发。用过的测试样本标为已见，新的方法选择需要新的独立确认。

## 结果与持续执行
可以压缩范围、借鉴和组合已有机制、使用实用工程技巧；原始数据、失败和负结果保留，不能靠弱化基线、挑样本、改评分或遗漏成本制造优势。合理通用优化同样给 B3。主指标和质量要求在本轮比较前确定，当前默认总 LLM 输入＋输出 tokens，发布耗时与质量必须同时报告。
沿用当前 VS Code 会话及原生 Goal；文档更新不代表原生状态已变更，不另开竞争执行器。阶段汇报用“新数字、主要差距、方法决定、下一项实际动作”，然后继续。完成上述必要证据和论文交付才标 complete；候选失败、预算耗尽、只写报告均不是完成。遵守宿主资源/生命周期限制，受限时保存准确续接点。
